# GAPS.md — slint-app (Slint 1.17.1)

## Spec coverage

All 7 functional requirements of SPEC.md were expressible directly in Slint —
**no functional gaps**:

1. Window title/size/resizable → `Window` with `preferred-width/height` (resizable by default).
2. Placeholder input → `LineEdit.placeholder-text`.
3. Add button appends trimmed text, clears input → `Button.clicked` callback into Rust;
   trim/empty check done on the Rust side of the callback.
4. Enter-to-add → `LineEdit.accepted(text)` callback (fires on Enter while focused).
5. Task rows with Delete button → `for task[i] in tasks:` repeater inside `ListView`.
6. Live counter → `tasks.length + " task(s)"` property binding (auto-updates when the
   Rust-side `VecModel` changes).
7. Scrolling → `ListView` scrolls natively when content overflows.

## Notes / friction (research data)

- **Clearing the input from Rust requires plumbing.** The `LineEdit` inside the
  component is not reachable from Rust; you must export a component-level
  two-way property (`in-out property <string> input-text <=> input.text;`) and
  set it from the callback handler. Every piece of state that crosses the
  Rust/.slint boundary must be declared explicitly in the component interface.
- **Logic split.** Because "ignore whitespace-only input" is business logic, the
  add/trim/clear logic lives in Rust while the event wiring lives in `.slint`.
  Simple apps end up with two files describing one interaction.
- **Codegen magic.** `slint::include_modules!()` pulls in code generated by
  `build.rs` (`slint-build`); types like `MainWindow` don't exist in the source
  tree. rust-analyzer resolves them fine, but greppability suffers, and
  `slint` and `slint-build` versions must be kept in lock-step (both pinned
  `=1.17.1`).
- **Default look is Fluent, not native macOS.** Since Slint 1.16 the default
  widget style is `fluent` on every platform (the platform-adaptive `native`
  alias still exists via `SLINT_STYLE=native` but receives less maintenance).
  The app therefore looks like a Windows app on macOS with default settings.
  (https://slint.dev/blog/default-native-style-change)
- **Runtime warnings:** none printed to stdout/stderr during a 10 s run on
  macOS (winit backend, FemtoVG renderer).
- **Launch verification:** release binary launched in background, confirmed
  alive after 10 s, and the window rendering was manually observed before it
  was killed. The original SPEC-1 screenshot artifact was not retained.
  Automated *interaction* (typing/clicking) was not scripted; Slint offers an
  experimental headless testing backend (`i-slint-backend-testing`) and, since
  1.17, an embeddable MCP server for driving a running app via its
  accessibility tree — using either would have required restructuring the app
  beyond the spec's "keep it minimal" rule.

## Measurements (Apple M4 Pro, macOS, rustc 1.96.1)

- Canonical clean `cargo build --release`: **42 s**; no-op incremental build:
  **4 s**. The earlier 115.8-second observation was not the controlled serial
  result.
- Release binary size: **15,434,560 bytes raw**; **13,873,752 bytes (13.2 MiB)
  stripped**.
- Dependencies (`--edges normal`): **302 unique crate names / 310 external
  name-version entries** — includes winit 0.30.13, glutin, FemtoVG, AccessKit,
  muda, taffy, fontique, Parley, HarfRust, swash, tiny-skia, softbuffer and
  copypasta. `rustybuzz`/`fontdb` are SVG/resvg-related transitive paths, not
  the principal Slint text stack.
- App LoC: `src/main.rs` 39 + `ui/main.slint` 52 + `build.rs` 3 = **94 lines**.
- Feature flags: **defaults only** (`std`, `backend-default`→winit,
  `renderer-femtovg`, `renderer-software`, `accessibility`, `compat-1-2`,
  `system-tray`). Nothing extra needed for the spec.
